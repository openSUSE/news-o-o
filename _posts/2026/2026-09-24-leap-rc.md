The [openSUSE](https://www.opensuse.org/) Release Team says [openSUSE Leap](https://get.opensuse.org/leap/) 16.1 is close to its [Release Candidate (RC)](https://get.opensuse.org/testing/) stage, with general availability planned for November. 

Leap Release Manager Luboš Kocman told the [openSUSE project mailing list](https://lists.opensuse.org/archives/list/project@lists.opensuse.org/) that the next build was expected to qualify as the RC. He said it should reach [openQA](https://openqa.opensuse.org/), which is openSUSE's automated testing system soon.

Kocman said recent changes merged into [SUSE Linux Enterprise Server](https://www.suse.com/products/server/) (SLES) 16.1 had caused an additional delay. 

The RC build is expect to arrive this week.

Testers can help by grabbing the latest image from [get.opensuse.org/testing](https://get.opensuse.org/testing), picking a test from the [Leap 16.1 manual test plan](https://en.opensuse.org/Portal:16.1/ManualTesting) (high-priority and untried tests help most), and recording their result with their openSUSE username and build number; participants will receive an [openSUSE Kudos](https://kudos.opensuse.org/) badge as a thank-you.

The [official roadmap](https://en.opensuse.org/openSUSE:Roadmap#Leap_16.1) had the RC build set for Sept. 16. The build is now running about a week behind that date.

The team plans to produce about one build per week during the RC phase to find and fix any remaining release blockers. 

The release team says testing matters most at this stage. Users and contributors can help by:

- Running their usual workflows on the RC builds and reporting critical issues to [openSUSE Bugzilla](https://bugzilla.opensuse.org/).
- Checking the non-blocking bug list for items assigned to them.

Saved bug queries and known issues are on the [openSUSE Known Bugs 16.1 wiki page](https://en.opensuse.org/openSUSE:Known_bugs_16.1#Existing_bugs), and the full schedule is on the [openSUSE Roadmap](https://en.opensuse.org/openSUSE:Roadmap#Leap_16.1).

Leap 16.1 and SLES 16.1 will launch on the same day because of feedback from the [Leap 16.0 release retrospective](https://en.opensuse.org/Portal:16.0/Retrospective#Release_process). Shipping together means Leap users won't face a gap between the release and the first maintenance updates. Those updates arrive with the SLES 16.1 GA and flow directly to Leap.

KDE users get the biggest jump: two Plasma feature releases and nine Frameworks releases, built on a newer Qt 6.11. On the server and virtualization side, QEMU moves to a new major version, MariaDB jumps to the 12 series, and PHP moves to 8.5.

There are currently no known release blockers. 

The original announcement and follow-up are in the [openSUSE project mailing list thread](https://lists.opensuse.org/archives/list/project@lists.opensuse.org/thread/KHRHDSARPUQE2N3AT6GGGNEQPF7QIVQF/).
